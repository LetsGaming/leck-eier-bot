New:

- `web/src/pages/MemberOverview.tsx` — the new `/members/:userId` page: profile header (avatar, display name, nickname, in-guild badge), audit timeline (joined/rules-accepted/left via `formatAbsolute`/`formatRelative`), registration status, birthday (with a link to `/birthdays`, read-only here), and event history (table linking each row to `/events/:eventId`). Distinguishes "still loading" (`loading && !member`) from "not found" (`!loading && !member`) so a 404 shows a dedicated empty-state card instead of an infinite spinner or crash.

## CommunitySnapshotSection design

- A single `.stat-grid` tile for `memberCount` (kept separate from the bot-owner stat grid above it).
- Three `.card-grid` cards, matching this dashboard's existing card/list visual language (reused `.attention-list` — the same `<ul>` styling Overview's attention card already used — rather than inventing new CSS):
  - **"Geburtstage diese Woche"**: each entry linked to `/members/:userId` when `userId` is present (falls back to plain text otherwise, matching `CommunitySnapshotBirthday.userId`'s nullability), with the resolved date shown muted/small.
  - **"Anstehende Events"**: each entry links to `/events/:id`, with start date + signup count shown muted/small.
  - **"Letzte Aktivität"**: each entry links to `/members/:userId` (always present per `CommunitySnapshotActivity`), with a German label per `event` (`joined`→"ist beigetreten", `left`→"hat den Server verlassen", `rulesAccepted`→"hat die Regeln akzeptiert") and a relative timestamp via `formatRelative`.
- Each of the three cards has its own "nothing here" `<p className="muted">` empty state, since `communitySnapshot`'s three list fields are independently and commonly empty (confirmed live: all three were empty on a freshly-seeded mock DB with only a handful of rows).
