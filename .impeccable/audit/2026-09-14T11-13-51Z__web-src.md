## Detailed Findings by Severity

### P1 — Major (WCAG AA violations / significant difficulty)

**[P1] `--border` fails UI-component contrast everywhere it's used**
Location: `web/src/theme.css:5`, used at `:264` (`.card`), `:370` (inputs), `:551` (`th`/`td`), `:1624` (dividers)
Category: Accessibility
Impact: A low-vision moderator can't reliably see where a card, input, or table row ends.
WCAG: 1.4.11 (3:1 minimum) — computed: vs `--bg` 1.24:1, vs `--bg-elevated` 1.35:1, vs `--bg-inset` 1.62:1. All fail.
Recommendation: Add `--border-strong` (~#5c5f66, ≈2.6–3:1) for boundaries that must be perceivable (inputs, interactive card edges); keep `--border` for purely decorative dividers.
Suggested command: `/impeccable colorize`

**[P1] `--accent-hover` used as hover-state link text — the same bug shape the recent fix targeted, just missed here**
Location: `web/src/theme.css:1840-1842` (`.back-link:hover`), `:1856-1858` (`.link-button:hover`)
Category: Accessibility
Impact: Hovering a link makes it harder to read, at the exact moment a user is interacting with it.
WCAG: 1.4.3 (4.5:1) — computed: 1.97:1 on `--bg`, 2.15:1 on `--bg-elevated`. Worse than the original 2.74:1 bug.
Recommendation: Add `--text-link-hover` (a darkened `--text-link`, not `--accent-hover`, which is a fill color).
Suggested command: `/impeccable colorize`

**[P1] `.badge.severe` unreadable against its own background**
Location: `web/src/theme.css:633-636`
Category: Accessibility
Impact: The single most severe attendance tier — the one an admin most needs to notice — is the hardest badge to read.
WCAG: 1.4.3 — computed: 1.71:1 over `--bg-elevated`, 1.60:1 over `--bg`.
Recommendation: Raise background alpha to ~0.35–0.4 or lighten text toward `#ff6b70`; verify against both surfaces.
Suggested command: `/impeccable colorize`

**[P1] Three more badge tiers fail contrast against their own tint**
Location: `web/src/theme.css:611-614` (`.ok`), `:621-624` (`.error`), `:628-631` (`.moderate`)
Category: Accessibility
Impact: Status badges throughout Commands, Birthdays, and Event-Anwesenheit read at reduced contrast.
WCAG: 1.4.3 — computed: `.ok` 3.54:1/3.27:1, `.error` 3.18:1 (lower on `--bg`), `.moderate` 3.54:1/3.28:1 — all fail 4.5:1.
Recommendation: These use the same hue for text and its own translucent tint, making contrast surface-dependent — raise tint alpha or switch to a fixed opaque background per badge.
Suggested command: `/impeccable colorize`

**[P1] Danger buttons borderline-illegible in both states**
Location: `web/src/theme.css:470-479` (`button.danger`, `:hover`)
Category: Accessibility
Impact: Destructive-action buttons — the ones needing the most careful reading before a click — render weakly.
WCAG: 1.4.3 — computed: default 3.35:1/3.66:1, hover (white-on-red) 3.77:1. All fail 4.5:1.
Recommendation: Add `--danger-fg`, a lightened foreground variant, mirroring the `--accent`/`--text-link` split; re-check the hover state separately.
Suggested command: `/impeccable colorize`

**[P1] SearchableSelect options are individually Tab-focusable**
Location: `web/src/components/SearchableSelect.tsx:251-263`
Category: Accessibility (keyboard)
Impact: Tabbing through a form with an open combobox holding "dozens or hundreds" of options (per its own docstring) forces the user through every option instead of skipping to the next field.
WCAG: 2.4.3 (focus order) / 2.1.1 pattern conformance
Recommendation: Add `tabIndex={-1}` to each option button — `aria-activedescendant` already drives virtual navigation correctly.
Suggested command: `/impeccable adapt`

**[P1] `.card-grid-registration` has no mobile override — overflows below ~590px**
Location: `web/src/theme.css:247-256`, used at `web/src/pages/Settings.tsx:226`
Category: Responsive Design
Impact: The Registrierung settings section forces horizontal scroll on any phone under ~590px, including the standard 320–375px test range.
Evidence: `minmax(560px, 1fr)` defined once, no `@media` override anywhere — unlike `.card-grid`, which correctly collapses at 420px (`theme.css:2028-2030`).
Recommendation: Add `.card-grid-registration { grid-template-columns: 1fr; }` inside the existing 700px breakpoint.
Suggested command: `/impeccable adapt`

## Patterns & Systemic Issues

1. **`--border` can't do its job anywhere it's used** — 1.2–1.6:1 against every surface, nowhere near 3:1. One new higher-contrast token fixes dozens of instances at once.
2. **Self-composited translucent badges lose contrast to whatever's behind them** — 4 of 5 badge variants use the same hue for text and its own tint, so contrast depends on the surrounding surface and never reliably clears 4.5:1.
3. **The `--accent`→`--text-link` fix from this session didn't reach every foreground use of accent-family colors** — `--accent-hover` still backs two hover-state texts at the same failure shape the fix targeted.

## Positive Findings

- **Zero hardcoded colors in any `.tsx`/`.ts` file** — every color decision lives in `theme.css`, so every fix above is a token change, not a hunt-and-patch.
- **`SearchableSelect.tsx`** implements a genuinely correct ARIA combobox (roles, `aria-activedescendant`, full keyboard handling, portal-based positioning) — well above what's typical without a component library.
- **`ConfirmContext.tsx` and `Tabs.tsx`** both implement correct non-trivial patterns (a working `alertdialog` with Tab-trap and Escape; a proper roving-tabindex tablist).
- **The 700/860/420px responsive breakpoint system and table→card stacking** are thoughtfully engineered — the `.card-grid-registration` miss is an isolated gap, not a sign of a missing strategy.
